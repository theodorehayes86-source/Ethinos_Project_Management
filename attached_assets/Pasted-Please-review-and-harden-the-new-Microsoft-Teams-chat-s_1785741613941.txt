## Objective

Microsoft Graph chat change-notification subscriptions expire regularly. The scheduler should renew active subscriptions before expiry without:

* Missing subscriptions
* Creating overlapping scheduler runs
* Silently leaving expired subscriptions broken
* Writing invalid expiry values
* Overloading Firebase or Microsoft Graph
* Exposing subscription identifiers unnecessarily
* Starting duplicate schedulers during hot reload or multi-instance deployment

Preserve the intended behaviour:

* Run every 10 minutes
* Renew subscriptions close to expiry
* Process both bot chats and regular chats
* Run once at server startup
* Use the existing distributed job-lock mechanism
* Log useful results without logging secrets

# 2. Validate renewal responses before writing to Firebase

The current code does:

```ts
const newExpiryStr = await renewChatSubscription(sub.id);
const newExpiresAt = new Date(newExpiryStr).getTime();

await writeFirebasePath(..., {
  id: sub.id,
  expiresAt: newExpiresAt,
});
```

This can write:

```ts
NaN
```

or an expiry value that is already in the past.

Add strict validation:

```ts
const newExpiresAt = Date.parse(newExpiryStr);

if (!Number.isFinite(newExpiresAt)) {
  throw new Error("Microsoft Graph returned an invalid subscription expiry");
}

if (newExpiresAt <= Date.now()) {
  throw new Error("Microsoft Graph returned an expired subscription");
}
```

Also verify the renewed expiry is meaningfully later than the previous expiry.

Do not overwrite a valid stored expiry with an invalid value.

# 7. Review concurrency inside each run

The current code renews subscriptions sequentially within each parent path:

```ts
for (const [chatKey, chatData] of entries) {
  await renewChatSubscription(...)
}
```

But it processes bot chats and normal chats concurrently with:

```ts

```

Review whether this is appropriate.

Requirements:

* Avoid overwhelming Microsoft Graph
* Avoid runs taking longer than the lock TTL
* Use bounded concurrency if there may be many subscriptions
* Do not use an unbounded `Promise.all()` over all chats
* Continue processing other subscriptions if one renewal fails

A small bounded concurrency limit such as 3–5 may be appropriate.

Use the project’s existing concurrency utility if one exists.

# 8. Fix lock TTL assumptions

The scheduler runs every 10 minutes and uses:

```ts
const LOCK_TTL_MS = 9 * 60 * 1000;
```

A lock shorter than the schedule interval does not guarantee that a slow run finishes before another instance starts.

If a run takes more than 9 minutes:

* The lock may expire while the original run is still active
* Another server instance may start the same renewal job
* The same subscription may be renewed concurrently

Review the `withJobLock()` implementation.

Use a TTL comfortably longer than the maximum expected job duration, for example:

```ts
const LOCK_TTL_MS = 15 * 60 * 1000;
```

or implement lock extension/heartbeat support if available.

The cron interval and lock TTL should not be chosen solely to be “just under” each other.

---

# 9. Use the same lock key for startup and scheduled runs

The current code uses:

```ts
"chat-subscription-renewal"
```

for scheduled runs and:

```ts
"chat-subscription-renewal-startup"
```

for startup runs.

This allows a startup run and scheduled run to execute concurrently because they use different locks.

Use the same lock key for both:

```ts
const JOB_LOCK_KEY = "chat-subscription-renewal";
```

Then:

```ts
withJobLock(JOB_LOCK_KEY, LOCK_TTL_MS, ...)
```

for both startup and cron execution.

This is particularly important if the server starts close to a 10-minute cron boundary.

# Recommended core structure

Adapt this to the project rather than copying blindly:

```ts
const JOB_LOCK_KEY = "chat-subscription-renewal";
const LOCK_TTL_MS = 15 * 60 * 1000;

let schedulerStarted = false;

export async function runChatSubscriptionRenewal():
  Promise<ChatSubscriptionRenewalResult> {
  logger.info("[ChatSubRenewal] Running subscription renewal check");

  const [botChats, chats] = await Promise.all([
    renewSubscriptionsUnder("teamsDMs/botChats", "botChats"),
    renewSubscriptionsUnder("teamsDMs/chats", "chats"),
  ]);

  const result = {
    botChats,
    chats,
    errors: [...botChats.errors, ...chats.errors],
  };

  logger.info(
    {
      botChats: sanitiseResultForLogs(botChats),
      chats: sanitiseResultForLogs(chats),
    },
    "[ChatSubRenewal] Renewal check complete"
  );

  return result;
}

export function startChatSubscriptionRenewalScheduler(): void {
  if (schedulerStarted) {
    logger.warn("[ChatSubRenewal] Scheduler already started");
    return;
  }

  schedulerStarted = true;

  cron.schedule("*/10 * * * *", () => {
    withJobLock(
      JOB_LOCK_KEY,
      LOCK_TTL_MS,
      runChatSubscriptionRenewal
    ).catch(error => {
      logger.error(
        { error },
        "[ChatSubRenewal] Scheduled renewal failed"
      );
    });
  });

  withJobLock(
    JOB_LOCK_KEY,
    LOCK_TTL_MS,
    runChatSubscriptionRenewal
  ).catch(error => {
    logger.error(
      { error },
      "[ChatSubRenewal] Startup renewal failed"
    );
  });

  logger.info(
    "[ChatSubRenewal] Scheduler started — checking every 10 minutes"
  );
}
```
