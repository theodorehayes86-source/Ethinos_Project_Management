Please fix and unify the **monthly recurring task functionality across both mobile and desktop task creation flows**.

## Current situation

The feature has already been added to both mobile and desktop, but the desktop version is either:

* Not showing the new controls
* Not entering the correct monthly mode
* Not saving the new fields
* Not generating recurring dates correctly
* Using an older task creation component
* Being hidden by conditional rendering

The mobile implementation also needs to be cleaned up so that both platforms use the same reliable logic.

The required use case is:

```text
Create a task that repeats monthly on the 5th
```

with optional weekend handling:

```text
Keep date as-is
Move to previous Friday
Move to next Monday
```

The existing mobile implementation includes the relevant state, recurrence fields and UI, but the reviewed patch contains duplicate and potentially broken code that must be corrected rather than copied as-is.

## Objective

Ensure the same complete monthly recurrence functionality works in:

* Mobile task creation
* Desktop task creation
* Client View task creation
* Team View task creation
* My Tasks
* Quick-add forms
* Checklist-derived task creation
* Any other place where a task can be added

Do not create separate incompatible implementations.

# 5. Use one shared recurrence data model

Both mobile and desktop forms must use the same state shape:

```js
repeatFrequency
repeatEnd
repeatDays
repeatMonthlyMode
repeatMonthlyWeek
repeatMonthlyDay
repeatDayOfMonth
repeatWeekendRule
```

Allowed monthly modes:

```js
'nth-weekday'
'specific-date'
```

The final task payload should follow these rules.

## Monthly nth-weekday mode

```js
repeatFrequency: 'Monthly',
repeatMonthlyWeek,
repeatMonthlyDay,
repeatDayOfMonth: null,
repeatWeekendRule: null
```

## Monthly specific-date mode

```js
repeatFrequency: 'Monthly',
repeatMonthlyWeek: null,
repeatMonthlyDay: null,
repeatDayOfMonth: Number(repeatDayOfMonth),
repeatWeekendRule
```

## Weekly mode

```js
repeatDays
```

Unused recurrence fields should be consistently set to `null` or omitted according to the existing data model.

Do not let mobile and desktop store different schemas.

For repeating tasks:

```text

```

```text

```

* Define and test shorter-month behaviour.
* Clamp to the last day of the month only if that is the intended rule.

# 12. Prevent silent recurrence fallback

Do not use a fallback such as:

```js
const occurrences = dates.length > 0 ? dates : [startDate];
```

for an invalid repeating schedule.

For:

```js
repeatFrequency !== 'Once'
```

if no valid dates are generated:

* Show a validation error
* Do not create a one-time task silently

Use `[startDate]` only for non-repeating tasks.
