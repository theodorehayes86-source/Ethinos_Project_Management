Please thoroughly test and validate the completed Team View permission implementation for CSMs and Business Heads. This is primarily a QA and verification exercise, not a redesign or refactor. Only recommend code changes where the implementation does not meet the business requirements below. Do not suggest low-priority improvements or cosmetic changes if the functionality is correct.

==================================================
BUSINESS REQUIREMENT
==================================================

For users with the role:

• Business Head (BH)
• Client Success Manager (CSM)

Team View should include:

1. Their direct reportee CSMs.
2. Team members allocated to clients owned by those direct-reportee CSMs.
3. Team members allocated to clients owned directly by the logged-in Business Head or CSM.

However, task visibility must always remain CLIENT-SPECIFIC.

They should ONLY see:

• Tasks belonging to those authorised clients.

They should NEVER see:

• Personal tasks
• Ethinos Internal tasks (unless that client is explicitly authorised)
• Tasks belonging to any other clients
• Tasks belonging to unrelated reporting branches
• All tasks for a visible employee simply because that employee is visible

Person visibility and task visibility are two separate permission checks.

TEST THE IMPLEMENTATION
==================================================

Review the completed implementation and confirm:

1. The reporting hierarchy is correct.
2. Direct-reportee CSMs are correctly included.
3. Team members allocated to authorised clients are included.
4. Unrelated client teams are excluded.
5. Person visibility is calculated independently from task visibility.
6. A visible employee does NOT expose all of their tasks.
7. Task visibility is filtered using permitted client IDs.
8. Personal tasks never appear.
9. Internal tasks only appear if they belong to an authorised client.
10. Other-client tasks never appear.
11. KPI cards use only permitted tasks.
12. Member detail screens use only permitted tasks.
13. Weekly dashboards use only permitted tasks.
14. Search respects permissions.
15. Desktop and mobile behave identically.
16. Existing Admin visibility has not been broken.
17. Existing Manager hierarchy permissions have not been broken.
