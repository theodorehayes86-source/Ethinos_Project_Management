## Priority 1: make failed task creation visible and recoverable

Inside `persistClientLogs()`, new tasks are currently created using a fire-and-forget operation similar to:

```js
set(
  newRef,
  sanitizeForFirebase(taskWithKey)
).catch(error => {
  console.error(
    '[PMT] Task create failed:',
    error
  );
});
```

The task is added to local state before Firebase confirms the save.

If creation fails, the task remains visible and the employee receives no warning.

Change this behaviour.

Preferred approach:

1. Migrate every ordinary task-creation action to the existing asynchronous `persistTaskCreate(clientId, taskData)` helper.
2. Await the helper.
3. Show a saving state while the task is being created.
4. Show a visible error if the write fails.
5. Do not show a success message before Firebase confirms the save.
6. Do not leave an unsaved task appearing as successfully created.
7. Prevent duplicate submissions while creation is in progress.

Review task creation in:

```text
artifacts/pmt-app/src/PMT/HomeView.jsx
artifacts/pmt-app/src/PMT/ClientView.jsx
artifacts/pmt-app/src/PMT/TeamView.jsx
artifacts/pmt-app/src/PMT/MasterDataView.jsx
artifacts/pmt-app/src/PMT/SettingsView.jsx
```

Pass `persistTaskCreate` into every view that creates tasks.

Avoid routing task creation through the compatibility `persistClientLogs()` diff writer.

## Priority 5: make mixed task operations atomic

The smart diff writer currently:

* creates new tasks through separate `set()` calls;
* updates and deletes existing tasks through a root multi-path `update()`.

This allows partial success.

Change task creation inside the diff plan so that new push-key task values are placed directly into the same `multiPathUpdate` object:

```js
const newRef = push(
  ref(db, `clientLogs/${clientId}`)
);

const taskKey = newRef.key;

multiPathUpdate[
  `clientLogs/${clientId}/${taskKey}`
] = sanitizeForFirebase({
  ...task,
  id: taskKey,
  taskKey,
});
```

Then submit one:

```js
await update(
  ref(db),
  multiPathUpdate
);
```

This allows one action containing creates, edits and deletes to succeed or fail together.

Do not issue separate fire-and-forget `set()` calls for new tasks from inside the diff writer.

## Priority 6: extract the task diff planner into a testable function

Move the pure comparison and Firebase-path generation logic out of `App.jsx`.

Suggested file:

```text
artifacts/pmt-app/src/lib/clientLogDiff.js
```

Suggested interface:

```js
export function buildClientLogUpdatePlan({
  previousLogs,
  nextLogs,
  createTaskKey,
}) {
  return {
    firebaseUpdates,
    finalLogs,
    createdTasks,
    updatedTasks,
    deletedTasks,
  };
}
```

The function must not call React setters or Firebase directly.

It should:

* support legacy array-shaped input;
* support push-key-shaped input;
* preserve existing `taskKey` values;
* generate keys for new tasks;
* write only changed fields;
* set removed fields to `null`;
* set deleted task paths to `null`;
* leave unrelated tasks untouched;
* produce one root multi-path update object.

`persistClientLogs()` should call this pure function and then execute the returned update plan.
