PART 1 — FIX TEAMS WEBHOOK DEDUPLICATION
==================================================

The Teams webhook comments say content-fingerprint deduplication was removed, but the code still calculates and writes a fingerprint using:

- sender
- first 200 characters of body
- one-minute time bucket

This can incorrectly suppress legitimate messages such as:

- “ok”
- “thanks”
- repeated short replies

sent by the same person within the same minute.

Fix this inconsistency.

Preferred behaviour:

1. Use the Microsoft Graph message ID as the primary idempotency key.
2. Keep the existing fast-path check against the stored message key.
3. Remove the sender/body/minute fingerprint logic unless there is a reliable cross-subscription event identity available.
4. Do not suppress legitimate repeated content.
5. Ensure duplicate webhook delivery of the same Graph message remains idempotent.

If a second deduplication mechanism is genuinely required, it must:

- Be based on a reliable event or message identity
- Not depend only on message content and minute bucket
- Use an atomic Firebase transaction rather than a read-then-write race
- Be documented accurately

Do not leave comments that contradict the implementation.
